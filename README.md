# Fame Over

A widescreen, 90s arcade-style fighting game with hand-made sprite animation. It follows on from
[Pixel Fighter](https://github.com/vonduzenstudios-create/Pixel-Fighter), whose jointed-part fighters
stay there as the "retro" game.

Stack: Vite + TypeScript + Canvas 2D. The game renders natively at 1920x1080 and scales the picture to
fit the window. Fighters are detailed, full-colour sprites 500 px tall (768x768 frames, see docs/ART_SPEC.md).

## Run it

```
npm install
npm run dev        # play at http://localhost:5173
npm test           # simulation, frame data and determinism tests
npm run build
```

Open `?viewer` (for example `http://localhost:5173/?viewer`) for the sprite viewer: it plays each
animation tick by tick with its boxes drawn on top. In a fight, F2 shows hurtboxes (blue) and active
hitboxes (red).

## Controls

| | Player 1 | Player 2 | Gamepad |
| --- | --- | --- | --- |
| Move | W A S D | Arrow keys | D-pad / stick |
| Light punch (gut) | U | [ or Numpad 4 | A |
| High punch (face) | I | ] or Numpad 5 | X |
| Low kick | J | ; or Numpad 1 | B |
| High kick | K | ' or Numpad 2 | Y |
| Block | L / Space | / or Numpad 0 | shoulders, triggers |

Down + HP uppercut, down + LK crouch kick, down + HK or back + LK sweep, back + HK roundhouse.
Holding back also blocks. Lights chain into lights when they connect.

## How it fits together

- `src/fight/`: the simulation. `fight.ts` runs a match, `fighter.ts` one fighter's state machine,
  `moves.ts` the shared moveset and its frame data, `ai.ts` the CPU. It is deterministic (same inputs,
  same fight) and reads only sprite *data*, never images, so online lockstep play can use it.
- `src/sprites/`: sprite sheets (`sheet.ts`) and the placeholder mannequin (`placeholder.ts`) drawn for
  any frame that has no art yet.
- `src/fighters/<id>/fighter.ts`: a fighter's animations (which frames, how long each is held) and moves.
  Art lives in `public/fighters/<id>/` (`sheet.json` plus `sheet-0.webp`, `sheet-1.webp`, ...).
- `src/net/` and `server/`: the lockstep netcode and matchmaking server carried over from Pixel Fighter,
  not wired into a menu yet.

## Adding art

New characters start with [docs/HANDOFF.md](docs/HANDOFF.md) and [docs/ART_PROMPT.md](docs/ART_PROMPT.md), the prompt for the art agents (it interviews you first). Art follows [docs/ART_SPEC.md](docs/ART_SPEC.md): one transparent 768x768 PNG per frame, feet at
(384, 736), facing right, in `frames/<animation id>/01.png`, ...

```
pip install pillow
python3 scripts/import_sheets.py "C:/Games/Fame Over/Graphics/Characters/<Character>" --out public/fighters/<id>
```

Animations made as videos go through `scripts/import_video.py` first (see docs/HANDOFF.md). That packs the frames into sheet pages and suggests hurt and hit boxes. Check them in `?viewer`, and put
corrections in the art folder's `overrides.json` (format at the top of the script). Missing frames keep
showing the placeholder.

Only original art goes in this repo: no frames, poses or sprites taken, traced or edited from another
game, including frames generated by editing them. To try art on your own machine before committing it,
import it into `public/local-art/<id>/` instead: that folder is git-ignored and, when present, wins over
the committed art.
